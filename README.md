# RecSort — 録画の整理

> 学校課題「録画の容量がいっぱいだが、どれを削除すればいいかわからないので選んでほしい」を解決する
> Windows 向けのアプリです。**ブラウザで開いて使います**（このパソコンの中だけで動く小さなサーバー + ブラウザの画面）。

PC 内のドライブを調べて、録画がどれくらい容量を使っているかを示し、**整理を考えるとよい録画を理由付きで提案** します。
録画をプレビューして「残す・保留・削除候補」を選び、最後に確認したファイルだけを Windows のごみ箱へ移します。

- 提案は決まったルール（重複・極端に短い・黒画面が多い・読み込み失敗・無音など）によるもので、AI の判定ではありません。
  動画の価値や面白さは判断しません。「不要」とは表示しません
- 自動削除・完全削除はしません。ごみ箱を空にしません
- データベースは使いません（設定・判断・保護・お気に入り・調査結果は JSON などの通常のファイル）
- 個人の録画やファイル情報を外部へ送信しません。サーバーはこのパソコンの中（127.0.0.1）だけで動き、インターネットには公開しません

バージョン: 1.0.0（統合版）。統合の経緯・採用したコード・テスト結果は `INTEGRATION_NOTES.md` を参照してください。
学校発表用の資料（設計判断・想定質問・変更履歴）は `docs/presentation/` にあります。

## 起動（Windows）

### 初回セットアップ（1回だけ）

1. Python 3.12 以上をインストールします（https://www.python.org/downloads/ 。インストール時に「Add python.exe to PATH」にチェック）。
2. （任意）FFmpeg をインストールします。録画の長さ・黒画面・無音・類似録画の判定とサムネイルに使います（下記「FFmpeg」）。
   ```
   winget install Gyan.FFmpeg
   ```
3. このフォルダの **`RecSortを起動.bat` をダブルクリック** します。
   初回だけ、このフォルダに `.venv`（Python の仮想環境）を作り、必要な部品（`requirements-web.txt`: numpy・Pillow・pywin32）を
   インターネットから入れます。終わると、そのまま RecSort が起動します。

### 普段の起動

`RecSortを起動.bat` をダブルクリックします。

- 黒いウィンドウ（サーバー）が開き、サーバーが応答できる状態になってから、既定のブラウザで **http://127.0.0.1:8765** が開きます
- 起動中は、ブラウザでこのアドレスを直接開いても（再読み込み・別のタブでも）使えます
- 終了するときは、黒いウィンドウを閉じるか Ctrl+C を押します（判断・保護などの記録は保存されます）
- すでに起動しているときにもう一度ダブルクリックすると、2つ目は起動せず、起動中の RecSort の画面を開きます
- ポート 8765 を別のアプリが使っているときは、その旨を表示して起動しません。そのアプリを終了するか、
  コマンドプロンプトで `RecSortを起動.bat --port 8766` のように別の番号を指定してください
- 部品が壊れた・足りないと表示されたときは、`.venv` フォルダを削除してからもう一度ダブルクリックすると、初回セットアップをやり直します
- 画面から終了するときは、設定の「RecSort を終了」を押します

### Windows にログインしたときに起動する（任意）

毎回バッチを起動せずに、ブックマークやリンクの **http://127.0.0.1:8765/** を開くだけで使いたい場合に設定します。

1. 初回セットアップの後、`RecSortを起動.bat` で RecSort を開きます
2. 設定 →「Windows にログインしたときに起動」→「ログイン時に起動するようにする」を押し、確認で「有効にする」を押します
3. 次のログインから、RecSort のサーバーだけが黒い窓なしで起動します（**ブラウザは開きません**。調査も自動では始めません）。
   使うときはブックマーク・リンクから http://127.0.0.1:8765/ を開きます

- 解除: 同じ設定画面の「自動起動を解除する」（コマンドでは `.venv\Scripts\python.exe main.py --autostart off`）。
  状態の確認は `--autostart status`、登録は `--autostart on`
- 登録先はこのユーザーだけの `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run` の「RecSort」
  （管理者権限は不要。ほかのアプリの登録には触れません）。タスクマネージャーの「スタートアップ アプリ」でも無効にできます
- RecSort のフォルダを移動したときは、設定画面に「場所と違います」と出ます。解除して、もう一度有効にしてください
- 自動起動で起動できなかったとき（ポートを別のアプリが使っている・保存データを読めない など）は、理由と直し方を
  ダイアログで表示し、`%LOCALAPPDATA%\RecSortV1\server.log` にも記録します
- 自動起動中に `RecSortを起動.bat` をダブルクリックすると、2つ目は起動せず、ブラウザで画面を開くだけです

**自動起動を使わない場合との違い:** 自動起動を使わない場合、PC を起動した直後は RecSort のサーバーが動いていないため、
http://127.0.0.1:8765/ を開いても「接続できません」になります。先に `RecSortを起動.bat` をダブルクリックしてください
（ブラウザも自動で開きます）。自動起動を有効にすると、ログイン後はいつでもこのアドレスを開くだけで使えます。

### 録画フォルダを指定して調べる

ホーム画面の「調べる録画フォルダ」に、録画があるフォルダのフルパス（例: `D:\録画\ゲーム 録画`）を入力して
「このフォルダを調べる」を押します。日本語や空白を含むパスも使えます。

- 「参照…」を押すと、このパソコンでフォルダを選ぶ画面が開きます（開けないときはパスを直接入力してください）。
  エクスプローラーの「パスのコピー」で付く前後の `"` は自動で外します
- フォルダが存在しない・フォルダでない・読み取る権限がないときは、画面に理由を表示し、調査を始めません
- 調査中は進み具合（見つかった本数・解析の段階）を表示します。調査中もほかの画面を操作でき、
  ページを再読み込みしても調査はそのまま続きます。ボタンの連打や再読み込みで同じ調査が二重に始まることはありません
- フォルダを指定すると、そのフォルダだけを調べます（指定を「外す」とすべて外すと、PC 全体を調べる既定の動きに戻ります）。
  指定は `settings.json` の `scan_folders` に保存され、次回の起動時の自動調査にも使います
- 録画は読み取るだけで、名前・中身・更新日時を変えません

### コマンドで起動する場合（開発用）

```
pip install -r requirements-web.txt
python main.py
```

| 起動方法 | 内容 |
|---|---|
| `python main.py` | **ブラウザ版（標準）**。起動すると自動で調査を始めます（設定で変更可） |
| `python main.py --no-browser` | ブラウザを自動で開かない（表示された URL を自分で開く） |
| `python main.py --port 8766` | 別のポート番号で起動する（環境変数 `RECSORT_PORT` でも指定可） |
| `python main.py --desktop` | デスクトップ版（PySide6。`pip install -r requirements.txt` が必要）。画面と操作の手本として残しています |

Windows 10/11、Python 3.12 以上（3.14 で確認）。FFmpeg は任意です（下記）。
ブラウザ版とデスクトップ版は同じ保存データを使います。記録が食い違わないよう、同時には起動できません。

### ブラウザ版のしくみと安全対策

- 画面は `storage_organizer/web_ui/`、サーバーは `storage_organizer/webapp.py`（Python の標準ライブラリだけ）。
  調査・整理候補・保存・ごみ箱への移動は、デスクトップ版と同じ処理をそのまま使います
- サーバーは 127.0.0.1 だけで待ち受けます（ほかのパソコンからは開けません）。Windows では、別のアプリが使っている番号に
  割り込まないよう、排他的に番号を確保します
- 起動確認用の `/api/health` だけは合言葉なしで答えます（アプリ名と版だけ。録画の情報は返しません）
- 起動ごとに作る合言葉（トークン）がない要求は断ります。ほかのサイトのページから、こっそり操作されないようにするためです
  （Host ヘッダーも確認します）
- 再生できるのは、調査で登録した録画だけです（任意のファイルは読ませません）。ブラウザが再生できない形式（.ts など）は
  「保存場所を開く」でエクスプローラーから確認します
- ごみ箱への移動は、最終確認と確認ダイアログで承認したときだけです（承認のない要求はサーバーが断ります）

## 画面と使い方

| 画面 | できること |
|---|---|
| ホーム | 録画の件数・合計容量、整理候補の件数と容量、重複を整理した場合の削減見込み、選んだ削除候補の合計、ドライブの空き容量。「どこから確認するとよいか」のおすすめ |
| ファイル一覧 | 録画の一覧（名前・形式・容量・更新日時・判断・お気に入り・保護・整理候補の理由・保存場所）。検索、判断での絞り込み、容量順・更新日時順・名前順などの並べ替え。選ぶとプレビュー（再生・停止・シーク・再生時間）とファイル情報・理由を表示 |
| 整理のおすすめ | 完全重複・類似録画・確認が必要な録画を理由付きで表示。比較して残す1本を選べる。目標容量（今より○GB 空けたい）からの提案もできる。チェックした録画を「削除候補に追加」 |
| 削除候補 | 削除候補にした録画の一覧 → 最終確認（名前・保存場所・件数・容量）→ ごみ箱へ移動 → 結果（移動した・安全確認で止めた・失敗を分けて表示） |
| 設定 | FFmpeg の場所、自動調査、調査する場所・除外する場所、キャッシュ、保護記録の初期化 |

ごみ箱へ移しただけでは空き容量は増えません。ごみ箱を空にすると増えます（画面にも表示します）。

### 判断の用語

| 用語 | 意味 |
|---|---|
| 未判断 | まだ判断していません |
| 残す | この録画は残しておきます |
| 保留 | あとで確認して決めます |
| 削除候補 | ごみ箱に移動する候補に追加します。まだ削除されません |
| 保護中 | 保護を解除するまでごみ箱へ移動できません |
| ★ お気に入り | 整理のおすすめから外します（「残す」に近い扱い）。保護とは別の状態で、外すと対象に戻ります |

判断・保護・お気に入りはアプリ全体で共通です。

## 調査（全ドライブの自動スキャン）

- ビデオ・デスクトップ・ダウンロードなどのフォルダ（Windows の既知フォルダ API で実際の場所を取得）を先に調べ、
  その後に内蔵ドライブ全体を調べます。起動時に自動で更新します（設定で変更可）
- 外付け・ネットワーク・リムーバブルドライブは自動では調べません（設定の「追加で調べる場所」で追加できます）
- Windows・Program Files・ProgramData・AppData・キャッシュなどのシステム・アプリの領域は除外します（既知フォルダ API で判定）
- リンク・ジャンクションはたどりません（循環・二重集計を防ぐ）。アクセスできない場所はスキップして件数を表示します
- オンライン専用（クラウドにだけある）ファイルは読み込みません（勝手にダウンロードしない）
- 調査は別スレッドで行い、一時停止・再開・キャンセルできます。全体の件数が分かるまで進み具合の割合は表示しません
- 一覧に登録するのは録画（動画ファイル）だけです。ほかの種類は「容量の内訳」の集計にだけ使います
- 変更のないファイルは、前回の解析結果を使い、再解析しません

## 整理候補のルール

| 理由 | 判定 | 扱い |
|---|---|---|
| 完全重複 | サイズで絞り、ファイル全体の SHA-256 で一致を確認（名前だけでは判定しない） | 各グループで必ず1本を残す（保護 → お気に入り → 最も古いもの）。提案どおり選択済み |
| 類似録画 | 長さがほぼ同じで、代表 12 場面の 75% 以上が一致し、一致しない場面が 1 か所以下（明暗差の小さい場面は、より厳しい一致の基準で比べる） | 同じ内容とは限らない。比較して残す1本を確定するまで選べず、確定後も**録画ごとに**選ぶ（最初は選んでいない） |
| 極端に短い | 再生時間 3 秒未満 | 要確認（未選択） |
| 黒画面が多い | 確認した 3 場面がほぼ真っ暗 | 要確認（未選択） |
| 読み込み失敗 / 再生できない可能性 | 動画として読み込めない・0 バイト・索引情報がない | 破損とは断定しない。要確認（未選択） |
| 音声がほぼ無音 | 音声トラックがあり、確認した 3 か所（各 10 秒）の最大音量がすべて -50 dB 未満 | 要確認（未選択）。測れない区間があれば判定しない |
| 大容量 | 100MB 以上（一覧に表示） | **これだけでは削除をおすすめしない**。目標容量を指定して足りないときだけ「要確認」に加える |

- 保護中・お気に入り・「残す」・保留・オンライン専用の録画は、おすすめに含めません
- 目標を満たすために基準を緩めたり、根拠のない候補を足したりしません。足りなければ不足分を表示します
- 同じファイル（別の表記・ハードリンク）を二重に数えません。別のドライブの録画は、目的のドライブの解放見込みに含めません

### 似た録画の比較画面

- 「違いのある場面」に、代表 12 場面それぞれの画像を録画ごとに並べ、一致（緑）・違う（赤）・比較できない（灰）を示します。
  場面を押すと、すべての録画をその位置に合わせます。最初は「違う場面だけ」を表示します
- 音声は自動では比べていません（画面にそう表示します）。「音声を比べる」で数区間（各 2 秒）の周波数の分布と音量を比べます。
  音声がない・無音・比べられないときは「音声の一致を確認できません」と表示します。
  「すべて同時に再生」と「この音を聞く」（聞く録画だけ音を出す）で、聞き比べられます
- **完全に同じ録画**（SHA-256 一致）の「これを残す」は、ほかのコピーをまとめて削除候補にします（従来どおり）
- **似た録画**の「これを残す」は、その録画を「残す」にするだけで、ほかの録画は変えません。
  削除候補にするときは、録画ごとに「削除候補にする」を押して確認します。保護中の録画は削除候補にできません
- 保護・移動直前の再確認・ごみ箱に入らない場合の中止は、どの場合も同じです

### 類似判定の基準の変更（測定結果）

合成動画で、変更前の基準と今の基準を同じ代表場面で比べました（`python tools/eval_similar_cases.py`、Linux）。

| 項目 | 変更前 | 変更後 |
|---|---|---|
| 再圧縮・解像度違い（見つけた／27 組） | 24 | 27 |
| 明暗差が小さい映像の再圧縮・縮小（／12 組） | 0 | 7 |
| 同じ映像で明るさ・コントラストだけ違う（／18 組） | 0 | 15 |
| 20 秒のうち 16 秒が共通の別動画（類似にした／3 組） | 3 | 0 |
| 一部（8/24 秒）だけ違う動画（類似にした／1 組） | 0 | 0 |
| 別の動画どうし（誤ってまとめた／248 組） | 12 | 0 |
| グループ化の時間（実動画 55 本） | 0.20 秒 | 0.33 秒 |
| グループ化の時間（合成した特徴 1,020 本、`tools/bench_similar.py` 相当） | 2.43 秒 | 2.44 秒 |

- 代表場面の取り出し（約 0.8 秒／本）は変わりません（保存済みの代表場面をそのまま使い、取り出し直しません）
- 明暗差が小さく、強く再圧縮した映像（5 組）は、今も見逃します（場面の相関が 0.1〜0.8 まで下がるため。基準を緩めると別の暗い動画を誤ってまとめるおそれがあるため、緩めていません）
- 音声だけ違う録画は、映像が同じなので類似に入ります。比較画面の「音声を比べる」で「違う区間があります」と表示されます

## ごみ箱への移動（安全対策）

- 移動は「削除候補」画面の最終確認と、確認ダイアログでの承認の後だけ行います
- 移動の直前に、ファイルの存在・スキャン後の変更（サイズ・更新日時）・保護・残す側の実在を確認し、問題があれば移動しません
- Windows の `IFileOperation`（pywin32）を使い、次の場合は移動しません（フェイルクローズ）
  - 固定ドライブ以外（USB・ネットワークなど）、ごみ箱が使えない、「ごみ箱に移動しない」設定、ごみ箱の最大サイズ超過
  - 削除直前の通知（`PreDeleteItem`）に「ごみ箱へ移す」指定がない（Windows が完全削除しようとしている）→ その場で中止
  - 移動後に、ごみ箱内の項目が作られたことを確認できない
- 完全削除・別の削除方法への切り替えは一切しません。結果は記録（`trash_log.jsonl`）し、移動・スキップ・失敗を分けて表示します
- 元に戻すときは、Windows のごみ箱から復元してください

## FFmpeg（任意）

録画の長さ・黒画面・無音・類似録画・サムネイルの判定に使います。アプリは **自動でインストールしません**。
設定で指定したフォルダ → PATH → WinGet でインストールした場所（`%LOCALAPPDATA%\Microsoft\WinGet\Links`・`Packages`）の順に探します。

```
winget install Gyan.FFmpeg
```

FFmpeg がなくても、録画の一覧・容量の集計・完全重複の検出・ごみ箱への移動は使えます。

## データの保存（データベース不使用）

保存先: `%LOCALAPPDATA%\RecSortV1`（以前の版の `RecSortAI`・`RecSort` とは別。以前のデータは読み書きしません）

| 内容 | ファイル |
|---|---|
| 設定（保存形式の版 `schema_version` を含む） | settings.json |
| 判断・保護・お気に入り・確認日時（パスごと） | user_state.json |
| 調査場所・スキップ・容量の集計・類似グループ | scan_state.json |
| 調査場所ごとの録画の一覧 | inventory/*.json.gz |
| 解析結果のキャッシュ（パス・サイズ・更新日時で照合） | analysis.jsonl（追記のみ） |
| ごみ箱への移動の記録 | trash_log.jsonl（追記のみ） |

- 保存は「一時ファイルに書く → fsync → 読み直して内容を確認 → 直前のファイルを .bak に残して置き換える」
- 壊れたファイルは消さずに `.broken-*` へ退避し、`.bak` から復旧します。保護の記録を復旧できないときは整理操作を止めます
- 判断はまとめて1回で保存し、確認日時は終了時などにまとめて保存します（選ぶたびに全体を書き直さない）
- 新しい版のアプリで保存されたデータ（`schema_version` が新しい）は変更しません
- 二重起動を防ぐロックを取ってから保存データを読み書きします
